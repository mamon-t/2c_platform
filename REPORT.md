# 2C Platform — Отчёт о реализованных подсистемах

**Проект:** 2C Platform — конфигурируемая платформа документ-событий для малого и среднего бизнеса
**Дата отчёта:** 21.08.2026
**Версия:** v0.1 (рабочая)

---

## 1. Архитектурное ядро: «Труба и Доски»

Построена на архитектуре Event Sourcing, где каждое действие пользователя записывается как неизменяемое событие. Все данные делятся на два слоя:

- **Труба (Event Store)** — поток событий, которые нельзя изменить или удалить. Каждое событие содержит: кто выполнил, когда, в какой компании, что именно произошло.
- **Доски (Objects)** — текущее состояние данных, вычисляемое из событий. Представляют собой «снимки» актуального состояния документов и справочников.

Такой подход обеспечивает полную историю изменений, возможность восстановления любой версии документа и защиту от подделки данных.

---

## 2. Система метаданных

Платформа полностью конфигурируема через метаданные — без перекомпиляции:

- **Типы сущностей** — определяют виды документов и справочников (накладные, заявки, договоры, справочники и т.д.)
- **Поля описания** — 17 типов полей: текст, число, валюта, дата, перечисление, ссылка на справочник, таблица, формула и др.
- **Состояния и переходы** — жизненный цикл документа (Черновик → Активный → Проведён → Отменён) с настраиваемыми правилами переходов
- **Макеты форм** — визуальная компоновка полей в форме редактирования

Изменение метаданных автоматически отражается на поведении интерфейса — новые поля, кнопки и переходы появляются без обновления приложения.

---

## 3. Универсальная коллекция объектов

Все документы и справочники хранятся в единой структуре:

- Каждый объект привязан к типу сущности и компании
- Данные хранятся в формате JSON — гибкость без миграций
- Каждое изменение сохраняет снимок предыдущей версии с причиной изменения
- Нумерация документов — автоматическая, по настраиваемому формату (префикс компании + код типа + порядковый номер)

**Операции над объектами:**
- Создание, редактирование, проведение, отмена
- Восстановление любой предыдущей версии
- Просмотр полной истории изменений

---

## 4. Валидация данных

Автоматическая проверка данных при сохранении:

- Обязательные и защищённые от изменения поля
- Проверка типов (число, дата, email, телефон, ссылка и др.)
- Проверка допустимых значений из перечислений
- Ошибки валидации отображаются в форме до сохранения

---

## 5. Транзакционная целостность

Все операции изменения документов выполняются атомарно:

- Запись события, обновление снапшота и нумерация выполняются в одной транзакции MongoDB
- При ошибке — полный откат изменений
- Исключение: частичная запись данных недопустима

---

## 6. Контроль доступа (RBAC)

Многоуровневая система разрешений:

- **Политики доступа** — 37 правил по умолчанию (чтение/создание/обновление/удаление для компаний, пользователей, ролей, документов, справочников, аудита, настроек)
- **Роли** — наборы политик доступа, назначаемые пользователям
- **Отказ по умолчанию** — доступ запрещён, если явно не разрешён
- **Приоритет** — запрещающие политики имеют приоритет над разрешающими
- **Компания** — объекты одной компании недоступны для другой (изоляция данных)

На фронтенде кнопки и элементы управления скрываются, если у пользователя нет соответствующего права.

---

## 7. Аудит и журнал действий

Единый журнал «кто что сделал» со следующими возможностями:

- **Журнал аудита** — запись каждого действия: вход, создание/удаление компаний, пользователей, ролей, документов, политик доступа, настроек
- **Журнал событий** — поток бизнес-событий: создание, обновление, проведение, отмена документов с полными данными о пользователе и времени
- **Детализация изменений** — для каждого изменения сохраняется «было → стало»
- **Фильтрация** — по пользователю, компании, типу действия, периоду, объекту
- **Иконки и названия** — каждое действие отображается с иконкой Font Awesome и русским описанием

---

## 8. Нумерация документов

Автоматическая генерация номеров:

- Формат настраивается для каждого типа сущности: префикс компании, код типа, длина порядкового номера
- Атомарная генерация — исключает повтор номеров даже при параллельных операциях
- Нумерация привязана к компании — каждая компания имеет свой набор номеров
- Сброс счётчика и превью следующего номера доступны в интерфейсе

---

## 9. Конвертация данных (WASM-плагины)

Загружаемые модули для импорта и экспорта данных:

- **Форматы импорта:** CSV, JSON, YAML, XML
- **Форматы экспорта:** CSV, JSON, YAML, XML
- **Plug-in архитектура** — модули загружаются как WASM-файлы, описывают свои возможности через JSON-метаданные
- **Drag-and-drop** — удобная загрузка файлов через интерфейс
- Журнал операций импорта/экспорта

---

## 10. Печать документов

Движок шаблонов для печатных форм:

- Подстановка полей документа, номера, даты, состояния
- Табличные данные и условная логика
- Редактирование шаблона с превью в реальном времени
- Формат шаблонов: `{{data.field_name}}`, `{{number}}`, `{{#each rows}}...{{/each}}`

---

## 11. Интерфейс

- **Sidebar-навигация** с фильтрацией по правам доступа
- **Динамические формы** — компоновка полей определяется метаданными
- **Тёмная и светлая темы**, включая системную
- **Диагностика подключения** — проверка MongoDB, версия, replica set
- **Страница «Мой доступ»** — просмотр назначённых прав

## Техническая платформа

| Компонент | Технология |
|-----------|-----------|
| Ядро | Rust (Tokio async runtime) |
| Десктоп | Tauri v2 |
| Интерфейс | Svelte 5 + TypeScript + Tailwind CSS v4 + Skeleton UI v5 |
| База данных | MongoDB 7.0+ (Replica Set) |
| Авторизация | JWT + Argon2id |
| Шаблоны | Handlebars-подобный синтаксис |
| Плагины | WASM (Extism/wasmtime) |
| Скрипты | Rhai (sandbox) |
| Иконки | Font Awesome 6 Free |
