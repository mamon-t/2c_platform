# Тестирование «Заявок» вживую (E2E)

Полный ручной сценарий проверки модуля. Два уровня формальности:
маршрут **без ЭЦП** (бытовые заявки) и **с ЭЦП** (финансово значимые).

## Подготовка (один раз)

1. **Собрать плагин:**
   ```sh
   cd wasm-modules/requests
   cargo build --target wasm32-unknown-unknown --release
   ```
2. Запустить приложение, войти `admin` / `admin` (SUPERADMIN).
3. **Установить модуль:** Прикладные модули → установить
   `requests_plugin.wasm`. Манифест сам создаст политики `requests.*`
   и включит модуль для компании.
4. **Тип сущности REQUEST** (Метаданные):
   - Создать тип: код `REQUEST`, имя «Заявка», kind = document.
   - Поля:
     | Код | Имя | Тип | Обяз. |
     |---|---|---|---|
     | title | Тема | string | ✓ |
     | priority | Приоритет | enum (low, medium, high, critical) | |
     | amount | Сумма | money | |
     | deadline | Срок | date | |
     | description | Описание | text | |
5. **Второй пользователь** (Пользователи): логин `ivanov`, роль — создать
   роль «Согласующий» с политиками `requests.read_all`, `requests.approve`,
   `requests.reject`; назначить ivanov'у профиль с этой ролью.

## Сценарий A — маршрут без ЭЦП (канцтовары)

1. Заявки → Маршруты → новый: код `OFFICE`, этап 1 — пользователь ivanov,
   ☐ «Требовать ЭЦП» **выключен**.
2. Мои заявки → Создать: тема «Бумага А4», приоритет low → Сохранить.
3. Отправить → маршрут OFFICE → кнопка «Отправить»
   (**без** выбора сертификата — поле ЭЦП скрыто).
4. Перелогиниться `ivanov` → Заявки → На согласовании → карточка видна.
5. Согласовать с комментарием → статус «Согласована».

**Проверить:**
- [ ] Заявка стала Posted, получила номер (`MAIN-REQUEST-000001`…)
- [ ] Журнал (События): `request.submitted` → `request.step_approved`
      → `request.completed`, stream `requests:req-N`
- [ ] Timeline в карточке: шаг approved, подписи нет (не требовалась)
- [ ] admin получил уведомление о согласовании

## Сценарий B — маршрут с ЭЦП (закупка)

1. Маршруты → новый: код `PURCHASE`, этап 1 — ivanov,
   ☑ «Требовать электронную подпись».
2. Если сертификатов нет — в модалке отправки нажать
   **«Создать тестовый»**, имя латиницей (например `Ivanov`).
   Повторить под другим пользователем при необходимости.
3. admin: заявку «Мониторы 10 шт», сумма 250000 → Отправить по PURCHASE
   (потребует сертификат + подпись).
4. ivanov → На согласовании → Согласовать (тоже требует сертификат).
5. Проверить timeline: у отправки и решения есть отметки подписи.

**Проверить:**
- [ ] Без выбранного сертификата кнопка блокируется с ошибкой
      SIGNATURE_REQUIRED
- [ ] После полного согласования заявка Posted с номером
- [ ] В карточке у каждого шага строка «подписан (N симв.)»
- [ ] Проверка отсоединённой подписи (опционально): Журнал → события
      объекта → DER из payload можно верифицировать через
      verify_document_signature

## Негативные проверки

| Действие | Ожидание |
|---|---|
| Повторный submit активной заявки | CONFLICT |
| Согласование чужим пользователем | FORBIDDEN (кнопок нет + API отклонит) |
| Cancel не инициатором | FORBIDDEN |
| before_submit hook: settings маршрута? нет — настройки МОДУЛЯ: | |
| `{"before_submit": "throw \"нет бюджета\";"}` в ModulesPage→настройки | submit падает, процесс не создаётся |
| Удаление маршрута, по которому идёт процесс | процесс продолжает жить (снимок в approval) |

## Известные границы MVP

- Уведомления только in-app (email — v0.3)
- approver_type=role сравнивает текущую роль профиля; смена роли
  между шагами учитывается на момент решения
- Эскалация по таймаутам этапов — не реализована
